# RIV-006 — Durable request identity under retries

Prospective protocol, 2026-11-24. Compare a SQLite transaction with no deduplication against one that atomically records request identity and payload alongside a counter increment. Both use BEGIN IMMEDIATE and the same workload. Trusted broker, local database, no direct untrusted writer. Test sequential replay, conflicting payload with same ID, concurrent identical requests (8 clients), injected failure before commit and retry, restart after commit with lost response. Each case starts with fresh database. Expected: durable broker commits one increment per unique accepted ID, rejects conflicting payload, rolls back injected failure; baseline repeats increments on retries. Record actual counter, receipts, errors and per-case outcomes. Separate process test uses spawned workers with independent connections; this is not OS privilege isolation. No claims about distributed exactly-once semantics, malicious database writers, or external products. Run twice and report deviations. Prior art: transactional idempotency keys and atomic deduplication are established techniques; contribution is a reproducible agent-action failure fixture, not invention of idempotency. Owner review and independent replication pending.
